# ติดตั้ง FloodThai ด้วยชุด ZIP

คู่มือสำหรับผู้รับชุดแจกจ่าย ไม่ต้องรู้ล่วงหน้าว่าโฮสต์ใช้ cPanel หรือ DirectAdmin
ตัวติดตั้งรองรับการติดตั้งใหม่เท่านั้น ไม่ใช่เครื่องมืออัปเดตหรือกู้คืนเว็บไซต์เดิม

## ก่อนเริ่ม

- PHP 8.3 ขึ้นไป พร้อมส่วนขยายที่ตัวติดตั้งตรวจให้
- ฐานข้อมูล MySQL/MariaDB **ว่างแยกจากเว็บอื่น** และผู้ใช้ที่มีสิทธิ์สร้าง/แก้ตารางเฉพาะฐานข้อมูลนี้
- HTTPS และกำหนด Document Root ของโดเมน/ซับโดเมนเป็นโฟลเดอร์ `floodthai/public` ได้
- Cron ทุกนาทีและ PHP CLI สำหรับงานอัตโนมัติ/คิว; CLI ต้องมี `proc_open` สำหรับ scheduler
- PHP เขียน `storage` และ `bootstrap/cache` ได้ ไม่ตั้ง 777 ทั้งระบบ

โฮสต์ที่ติดตั้ง WordPress ได้อาจไม่รองรับครบ ส่งรายการนี้ให้ผู้ให้บริการตรวจได้เลย
หากเปลี่ยน Document Root ไม่ได้ ให้ผู้ให้บริการช่วยตั้งซับโดเมนที่ชี้ไป `public` ห้ามย้าย `index.php` ไปไว้โฟลเดอร์หลักหรือเปิด `.env`/`vendor` สู่สาธารณะ

## 1. อัปโหลด

1. แตก ZIP ใน File Manager ได้โฟลเดอร์ `floodthai` ซึ่งมี `vendor` พร้อม ไม่ต้องใช้ Composer บนโฮสต์
2. ตั้ง Document Root เป็น `floodthai/public` และเปิด HTTPS
3. สร้างฐานข้อมูลและผู้ใช้ฐานข้อมูลใหม่ เก็บชื่อเต็มรวม prefix เช่น `account_floodthai`
4. เปิด `https://โดเมนของคุณ/install.php` ตัวติดตั้งตรวจความพร้อมก่อนเขียนการตั้งค่า

## 2. ยืนยันเจ้าของและกรอกข้อมูล

1. ตัวติดตั้งสร้างรหัสเฉพาะเครื่องใน `storage/app/installer/setup-key.php` **ด้านนอก public**
2. อ่านค่า `token` จาก File Manager/FTP แล้วกรอกบนหน้าติดตั้ง รหัสนี้ไม่อยู่ใน ZIP และไม่แสดงในเว็บ
3. ตั้งชื่อระบบ URL HTTPS ฐานข้อมูล และเบอร์/รหัสผู้ดูแลใหม่ ไม่มีรหัสผู้ดูแลร่วมกัน
4. เลือก **โฮสต์ทั่วไป** หากไม่แน่ใจ หน้าจออัปเดตข้อมูลเป็นระยะ; **VPS** เปิด Reverb เพิ่มภายหลังได้ ยังไม่เปิดอัตโนมัติ
5. ระบบปฏิเสธฐานข้อมูลที่มีตารางแล้ว ไม่ล้าง ไม่เขียนทับ และไม่เปลี่ยน APP_KEY ของเว็บไซต์ที่ติดตั้งอยู่แล้ว
6. กดดำเนินแต่ละขั้น: สร้างตาราง → สร้าง 77 จังหวัด/บทบาท/ผู้ดูแล → ล็อกตัวติดตั้ง

หากขั้นตอนหยุด ให้โหลดหน้าติดตั้งใหม่และยืนยันรหัสเดิมเพื่อดำเนินขั้นตอนที่ค้างต่อ อย่าลบ `.env` หรือเปลี่ยน `APP_KEY` เพราะใช้เข้ารหัสข้อมูลสำคัญ
เมื่อสำเร็จแล้วตัวติดตั้งล็อกถาวร เก็บ `.env` และฐานข้อมูลสำรองคู่กันไว้ในพื้นที่ปลอดภัย ไม่ส่งให้ผู้อื่น

## 3. ตั้งงานอัตโนมัติ — ต้องทำก่อนเปิดรับเหตุจริง

เข้าสู่ระบบ แล้วเปิด `/admin/hosting` เพื่อดูความพร้อมและคำสั่งที่ตรงกับเครื่อง
ผู้ดูแลใหม่ต้องตั้งยืนยันตัวตน 2 ชั้นก่อนเข้าใช้งานหลังบ้าน

สำหรับโฮสต์ทั่วไป ตั้ง Cron **ทุกนาที** ในแผงควบคุม:

```sh
cd /home/ACCOUNT/floodthai && /PATH/TO/PHP artisan flood:cron
```

แทน ACCOUNT และ PATH/TO/PHP ด้วยค่าของโฮสต์ ขอผู้ให้บริการได้ ไม่ใช้ PHP เวอร์ชันเก่าคนละตัวกับเว็บไซต์
คำสั่งนี้รัน scheduler และระบายคิวแบบจบเป็นรอบ ไม่ใช้ worker ที่ต้องเปิดทิ้งไว้ มีตัวกันการรันซ้อน
ไม่สร้าง URL ให้บุคคลทั่วไปเรียกงานเบื้องหลังผ่านเว็บ

สำหรับ VPS ใช้ scheduler/queue worker ตาม `docs/DEPLOY.md` และ Supervisor เมื่อต้องการ Reverb
ทั้งสองรูปแบบยังต้องตรวจว่าตารางเวลาและคิวมี heartbeat ล่าสุดจริง; หน้าเว็บเปิดได้อย่างเดียวไม่ถือว่าระบบเตือนภัยพร้อม
งานที่ใช้เวลานานหรือมีหลายจังหวัดพร้อมกันควรใช้ VPS และทดสอบโหลดก่อนเกิดเหตุ

## 4. ตั้งค่าก่อนใช้งาน

- ตั้งจังหวัด พิกัด ขอบเขต สายด่วน ศูนย์พักพิง สถานีวัดน้ำ และประกาศความเป็นส่วนตัว
- รายชื่ออำเภอตั้งต้นมีเฉพาะจังหวัดนำร่อง ขอบเขต/ตำบลต้องนำเข้าของจริง ไม่ได้เติมข้อมูลจำลอง
- ทดสอบฟอร์มขอความช่วยเหลือ รายงานน้ำ การรับงาน และการสำรอง/กู้คืน
- เว็บไซต์ใหม่ยังไม่เปิดศูนย์หรือรับเหตุเอง ผู้ดูแลเปิดจังหวัดหลังตรวจความพร้อมแล้ว
- รูปที่อัปโหลดส่งผ่านแอปได้แม้โฮสต์ไม่ให้สร้าง symbolic link ไม่ต้องเปิดพื้นที่ตั้งค่าหรือข้อมูล private
- ตั้ง SMTP/LINE ภายหลังตามที่ใช้จริง และตรวจสิทธิ์/ค่าใช้บริการข้อมูลอากาศและเรดาร์ก่อนใช้งานจริง

## อัปเดตเว็บไซต์ที่มีข้อมูลแล้ว

สำรองฐานข้อมูล รูป และ `.env` ก่อน อัปโหลดเฉพาะโค้ดใหม่ เก็บคีย์เดิมและข้อมูลเดิม แล้วให้ผู้ดูแลรัน migration/refresh cache ตาม `docs/DEPLOY.md`
**ห้ามใช้ตัวติดตั้งใหม่กับฐานข้อมูลเดิม ห้ามใช้ migrate:fresh บนเว็บไซต์จริง**

## สำหรับผู้แจกจ่าย

สร้างชุดด้วย `php artisan flood:package` (ต้องมี Composer และ PHP zip บนเครื่องสร้าง)
หรือระบุ Composer PHAR: `php artisan flood:package --composer=/path/to/composer.phar`
ZIP และ SHA-256 อยู่ใน `output/releases` เตรียม dependencies `--no-dev` ในโฟลเดอร์แยก ไม่แตะ vendor ที่ใช้พัฒนาระบบ
ไม่รวม `.env`, log, ฐานข้อมูล, รูปที่อัปโหลด, รหัสติดตั้ง, ไฟล์แคชเดิม หรือข้อมูลจากเครื่องผู้แจก
ไฟล์ staging อยู่ใน `output/release-builds` สำหรับตรวจสอบ ไม่ใช่โฟลเดอร์เว็บไซต์

ข้อกำหนดอ้างอิง: https://laravel.com/framework/docs/13.x/deployment และ https://laravel.com/framework/docs/13.x/scheduling
ชุดโปรแกรมที่แจกฟรีไม่รวมค่าโฮสต์ และไม่ได้แปลว่าสามารถใช้บริการ API ภายนอกได้ทุกวัตถุประสงค์
