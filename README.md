# ศูนย์ช่วยเหลือน้ำท่วม (FloodThai Command Center)

ระบบหลังบ้านศูนย์สั่งการน้ำท่วมรายจังหวัด Laravel 13 + MySQL 8 + Bootstrap 5 (Super App UI) + Leaflet

## ชุดแจกจ่ายติดตั้งง่าย

ดาวน์โหลด **ZIP พร้อมใช้งาน** และไฟล์ตรวจสอบ SHA-256 จาก [GitHub Releases](https://github.com/naiyachonponthong/water-map/releases/latest)
อย่าใช้ปุ่ม Code → Download ZIP แทนชุดติดตั้ง: ZIP ซอร์สโค้ดไม่มี `vendor`

อ่าน [คู่มือติดตั้งผ่านเว็บ](docs/INSTALL-EASY.md) หรือเลือก [Plesk](docs/INSTALL-PLESK.md) / [cPanel](docs/INSTALL-CPANEL.md) / [DirectAdmin](docs/INSTALL-DIRECTADMIN.md)
ผู้แจกจ่ายสร้าง ZIP พร้อม dependencies ด้วย `php artisan flood:package` (ไม่รวม .env หรือข้อมูลจากเครื่อง)
ผู้รับอัปโหลด ZIP → ตั้งเว็บไซต์เป็น public → เปิด `/install.php` → ตั้งบัญชีผู้ดูแลของตัวเอง
ติดตั้งแล้วเปิด `/admin/setup` ใช้ผู้ช่วย 5 ขั้น: จังหวัด → หน่วยงาน → เจ้าหน้าที่/พื้นที่ → โฮสต์/Cron → ทดสอบก่อนเปิดจริง
หน้าผู้ช่วยไม่เปิดรับเหตุแทนคุณ และแยกการตั้งค่าตามจังหวัด ตัวติดตั้งไม่เขียนทับฐานข้อมูลเดิม

แจกให้ใช้และแก้ไขฟรีตาม [LICENSE.md](LICENSE.md) โดยคงเครดิต **Naiyachon ponthong** และแนบข้อกำหนดเมื่อแจกต่อ
สิทธิ์ของ dependencies/แผนที่/API เป็นของเจ้าของเดิม ไม่รวมค่าโฮสต์หรือค่าบริการภายนอก

## ชุดนี้มีอะไร

### ใหม่ในรุ่น 1.1.0

- **พื้นที่ของฉัน** จำจังหวัด/อำเภอ/ตำบลไว้ในเครื่องได้ 5 พื้นที่ ไม่มีการเก็บพิกัดส่วนตัว
- **ภาพรวมและกราฟสาธารณะ** ฝนรายชั่วโมง ระดับน้ำย้อนหลังพร้อมตลิ่ง และรายงานน้ำท่วมตามพื้นที่ ใช้ค่าจริง เว้นช่องว่างเมื่อไม่มีข้อมูล
- **ความสดของข้อมูล** แยกเวลาดึงกับเวลาตรวจวัด ThaiWater/Open-Meteo/RainViewer พร้อมแจ้งปัญหาต้นทางบนหน้าศูนย์สั่งการ

อ่าน [คู่มือพื้นที่ของฉัน](docs/MY-AREA.md) และ [วิธีอัปเดตจาก 1.0.0](docs/RELEASE-v1.1.0.md) โดยรักษาฐานข้อมูล `.env` และรูปเดิม ใช้ `php artisan flood:upgrade` หลังสำรอง ไม่ใช้ตัวติดตั้งซ้ำ

- โครงระบบ Super App UI (rail ซ้าย, topbar, ค้นหาเมนู Ctrl K, bottom nav มือถือ, PWA)
- เข้าสู่ระบบด้วยเบอร์โทร + รหัสผ่าน หรือ LINE Login, สมัครขอใช้งาน, รออนุมัติ
- บทบาท 7 แบบ + สิทธิ์ 23 รายการ (spatie/laravel-permission) ผูกกับจังหวัด
- 77 จังหวัด + อำเภอจังหวัดนำร่อง (ฉะเชิงเทรา ชลบุรี) + นำเข้าขอบเขตอำเภอ/ตำบลจาก GeoJSON
- แดชบอร์ดศูนย์สั่งการ: KPI, รายการความพร้อมเปิดศูนย์, แผนที่ขอบเขต, ความเคลื่อนไหวล่าสุด
- ผู้ใช้และสิทธิ์: อนุมัติ กำหนดบทบาท ระงับ ตั้งรหัสผ่านใหม่
- จังหวัดทั้งหมด (ผู้ดูแลระบบสูงสุด): เปิด/ปิดศูนย์สั่งการ, รับแจ้งทางเว็บ, พิกัดกลาง
- ตั้งค่าจังหวัด: สีธีม สายด่วน ประกาศ จุดกลางแผนที่ สวิตช์ศูนย์ เกณฑ์การทำงาน น้ำหนักคะแนนเร่งด่วน เบอร์ฉุกเฉิน ลิงก์ภายนอก
- ประวัติการใช้งาน (audit log) ทุกการเพิ่ม แก้ไข ลบ เข้าสู่ระบบ เก็บ 365 วัน
- หน้าเว็บประชาชนพื้นฐาน `/provinces` และ `/{slug จังหวัด}` (เบอร์ฉุกเฉิน ลิงก์ข้อมูลน้ำ สถานะศูนย์)

## เฟส 2: Request Help

- ฟอร์มขอความช่วยเหลือ 4 ขั้น `/{จังหวัด}/help` (GPS, ปักหมุด, วางลิงก์ Google Maps/LINE รวมลิงก์ย่อ, เก็บร่างในเครื่อง, แนบรูป 3 รูป, กันบอท + จำกัดความถี่)
- เปิดเฉพาะเมื่อจังหวัดเปิดศูนย์และเปิดรับแจ้งทางเว็บ ไม่งั้นแสดงเบอร์ฉุกเฉิน
- เลขคำขอ `FL{รหัสจังหวัด}-{ปีเดือน พ.ศ.}-{ลำดับ}` ใช้ lockForUpdate กันเลขซ้ำ
- หน้าติดตาม `/track` (ลิงก์เซ็นชื่อ หรือเลขคำขอ + 4 ตัวท้ายเบอร์) ปุ่มปลอดภัยแล้ว / สถานการณ์แย่ลง / ส่งข้อมูลเพิ่ม แชร์ลิงก์ทาง LINE
- กันซ้ำ: เบอร์เดิมที่มีเคสเปิด = รวมเข้าเคสเดิมอัตโนมัติ, ต่างเบอร์แต่อยู่ใกล้ = ติดธง "อาจซ้ำ" ให้เจ้าหน้าที่ตัดสิน (ไม่รวมเอง เพราะอาจเป็นเพื่อนบ้านคนละหลัง)
- คะแนนความเร่งด่วนตามน้ำหนักในหน้า ตั้งค่า + น้ำเกินอกที่มีผู้ป่วยติดเตียง/ผู้พิการ/เด็กเล็ก = วิกฤตเสมอ คำนวณใหม่ทุก 5 นาที (`flood:recalc-priority`)
- หลังบ้าน: รายการเคสแยกแท็บ + แผนที่ + แจ้งเตือนเคสใหม่พร้อมเสียง, หน้ารายละเอียด (คัดกรอง, เปลี่ยนสถานะ, ปิดเคส, ปรับความเร่งด่วน, รวมเคส, บันทึก/โทร), รับแจ้งทางโทรศัพท์
- เบอร์โทรเก็บแบบเข้ารหัส เห็นเต็มเฉพาะผู้มีสิทธิ์ cases.manage

ต้องรัน `php artisan schedule:run` ทุกนาที (cron) เพื่อให้คะแนนเพิ่มตามเวลารอ

## เฟส 3: ทีมกู้ภัยและการสั่งการ

- ทีม สมาชิก (หนึ่งคนหนึ่งทีม) ยานพาหนะ (เรือ รถยกสูง รถพยาบาล ฯลฯ) สถานะทีม พร้อม/ติดภารกิจ/พัก/ไม่ออกปฏิบัติ
- แนะนำทีม: ยานพาหนะเหมาะกับระดับน้ำก่อน > ทีมว่าง > ถึงเร็ว (ระยะเส้นตรง × 1.3 ÷ ความเร็วยานพาหนะ)
- กระดานสั่งการ 6 คอลัมน์ ลากการ์ดตามขั้นตอน รีเฟรชทุก 20 วินาที
- เสนองานแล้วทีมไม่ตอบใน 10 นาที (ตั้งได้) เคสกลับเข้าคิวเอง (`flood:expire-offers` ทุกนาที)
- หน้า งานของทีมฉัน สำหรับหัวหน้าทีม/สมาชิก: รับ/ปฏิเสธ เริ่มเดินทาง ถึงแล้ว ปิดงาน หยิบเคสใกล้ตัว ส่งพิกัดทุก 60 วินาที
- ผู้แจ้งเห็นชื่อทีมและเวลาที่คาดว่าจะถึงในหน้าติดตาม ผู้แจ้งกดปลอดภัยแล้ว งานของทีมถูกปิดและทีมว่างทันที

## เฟส 4: แดชบอร์ดศูนย์สั่งการแบบ realtime

- แดชบอร์ด `/admin`: ตัวเลขสด, คิวเคสด่วน, แผนที่เคส + ทีม (พิกัดสด/ฐาน), ความเคลื่อนไหวของเคส
- โหมดทีวี `/admin/tv` จอมืดสำหรับห้องสั่งการ มีนาฬิกา เต็มจอ เสียงเตือนเคสวิกฤต
- Realtime ด้วย Laravel Reverb ผ่านช่องส่วนตัว `province.{id}` และ `team.{id}` (ส่งเฉพาะเลขเคส/สถานะ ไม่ส่งชื่อเบอร์)
- ไม่ได้เปิด Reverb หรือ Reverb ล่ม: ระบบยังทำงานปกติ หน้าจอดึงข้อมูลทุก 20 วินาทีแทน การบันทึกเคสไม่พัง
- กระดานสั่งการ รายการเคส และหน้างานของทีม อัปเดตทันทีเมื่อมี event (ทีมได้เสียง + สั่นเมื่อศูนย์เสนองาน)

เปิด realtime:

```bash
# .env
BROADCAST_CONNECTION=reverb
REVERB_HOST=ชื่อโดเมน   REVERB_PORT=443   REVERB_SCHEME=https
php artisan reverb:start --host=0.0.0.0 --port=8080   # ให้ Nginx proxy wss ไปที่พอร์ตนี้ และรันด้วย supervisor
```

## เฟส 5: Field Dashboard (แอปภาคสนาม)

- `/field` แอปมือถือ (PWA ติดตั้งลงเครื่องได้) แท็บ: งานของฉัน, รอบตัวฉัน, แผนที่, ทีม, SOS ทีมกู้ภัยล็อกอินแล้วเข้าหน้านี้อัตโนมัติ
- ใช้ตอนเน็ตไม่เสถียรได้: เก็บสถานะล่าสุดในเครื่อง ทุกการกดเข้าคิวก่อนแล้วส่งเองเมื่อมีสัญญาณ เซิร์ฟเวอร์ทำงานครั้งเดียวต่อปุ่มที่กด (ตาราง `field_actions`) ส่งซ้ำไม่เกิดผลซ้ำ ถ้าศูนย์เปลี่ยนงานไปแล้ว แอปแจ้งเหตุผลแทนการพัง
- Service worker เก็บหน้าแอป ไฟล์ และแผ่นแผนที่ที่เคยดูไว้ (สูงสุด 1,500 แผ่น)
- รับหลายเคสในรอบเดียว: เรียงจุดแวะให้ (เคสวิกฤตก่อน แล้วใกล้สุดก่อน) และเปิด Google Maps แบบหลายจุด
- ยืนยันระดับน้ำจริงจากหน้างาน บันทึกถึงศูนย์ ถ่ายรูปแนบเคส ส่งพิกัดทุก 60 วินาที
- SOS: กดค้าง 2 วินาที เลือกประเภท (กำลังเสริม / บาดเจ็บ / เรือเสีย / อื่นๆ) ศูนย์เห็นแถบแดงพร้อมเสียงบนแดชบอร์ดและโหมดทีวี กดรับทราบ/คลี่คลาย ทีมกดปลอดภัยแล้วเองได้

## เฟส 6: จุดเสี่ยงและครัวเรือนกลุ่มเปราะบาง

- **จุดเสี่ยง** (`/admin/risks`): ปักหมุดพร้อมรัศมี หรือวาดโซนด้วย leaflet-draw, ตั้งระดับน้ำที่ให้เตือน, นำเข้าจาก CSV / KML (Google My Maps) / GeoJSON
- **ประชาชนเสนอจุดเสี่ยง** ที่ `/{จังหวัด}/risks/propose` จุดจะรอผู้ตรวจอนุมัติก่อนขึ้นเว็บ (มีตัวเลขค้างบนเมนู)
- **ประกาศระดับน้ำรายตำบล**: ศูนย์ประกาศได้หลายตำบลพร้อมกัน มีเวลาหมดอายุ ใช้เมื่อรู้ว่าน้ำมาถึงก่อนจะมีคนแจ้ง
- **RiskEngine** ทำงานทุก 5 นาที (`php artisan flood:evaluate-risks`) อ่านระดับน้ำจากเคส 12 ชม.ล่าสุดและประกาศของศูนย์
  - จุดเสี่ยงในรัศมี/โซนที่น้ำถึงเกณฑ์ → สถานะ "ถูกคุกคาม" ขึ้นแผนที่ศูนย์สั่งการ ทีวี แอปภาคสนาม และเว็บประชาชน
  - ครัวเรือนเปราะบางที่น้ำถึงระดับที่ตั้ง (ค่าเริ่มต้น ระดับ 2) → เปิดเคส "ตรวจเยี่ยมเชิงรุก" เข้าคิวรอทีมให้เอง ไม่เปิดซ้ำในช่วง cooldown
  - เคสเชิงรุกไม่ถูกนับเป็นแหล่งระดับน้ำ ป้องกันการลามเป็นทอดๆ
- **ทะเบียนครัวเรือนเปราะบาง** (`/admin/vulnerable`): เบอร์โทรเข้ารหัส, บันทึกความยินยอม, นำเข้า CSV จาก อสม./รพ.สต. (ข้ามรายการซ้ำ), บันทึกผลเยี่ยม เลือก "ต้องการความช่วยเหลือ" แล้วเปิดเคสทันที
- **แอปภาคสนาม**: งานที่มาจากทะเบียนแสดงภาวะ ข้อมูลผู้ดูแล และปุ่ม "ผลเยี่ยมบ้าน" (ใช้ออฟไลน์ได้), เตือนจุดเสี่ยงใกล้ทีม 5 กม., ชั้นจุดเสี่ยงบนแผนที่
- ทีมเห็นข้อมูลครัวเรือนเฉพาะเคสที่ได้รับมอบหมาย ไม่เห็นทะเบียนทั้งหมด

## เฟส 7: รายงานระดับน้ำจากประชาชน

- **ประชาชนแจ้งระดับน้ำ** ที่ `/{จังหวัด}/report`: ใช้ GPS หรือปักหมุด เลือกระดับน้ำจากภาพ บอกแนวโน้ม (ขึ้น/ทรงตัว/ลด) แนบรูปได้ 3 รูป ไม่ต้องล็อกอิน
- **แผนที่สถานการณ์** ที่ `/{จังหวัด}/map`: รายงานระดับน้ำ (จางลงตามอายุ หมดอายุตาม `report_expire_hours`) + จุดเสี่ยง, กรองตามระดับ, ปุ่มแจ้งระดับน้ำและขอความช่วยเหลือ
- **กันข้อมูลรก/ปลอม**
  - เครื่องเดิมแจ้งซ้ำในรัศมี 150 ม. ภายใน 1 ชม. = อัปเดตรายงานเดิม
  - คนต่างเครื่องแจ้งห่างกันไม่เกิน 300 ม. ระดับต่างกันไม่เกิน 1 ขั้น = ยืนยันกันเอง
  - คนในพื้นที่กดในป๊อปอัป: ยังท่วมอยู่จริง (ต่ออายุ) / น้ำลดแล้ว (2 เสียง หมดอายุใน 1 ชม.) / ข้อมูลไม่ถูกต้อง (3 เสียง ซ่อนรอตรวจ) หนึ่งเสียงต่อเครื่อง
  - จำกัด 4 รายงาน / 10 นาที ต่อเครื่อง, รายงานนอกจังหวัดรอตรวจ, สวิตช์ "ตรวจรายงานก่อนแสดง" และ "เปิดรับรายงาน" ในหน้าตั้งค่า
- **เชื่อมระบบเตือน**: เฉพาะรายงานที่น่าเชื่อถือ (มีคนยืนยัน หรือเจ้าหน้าที่/ทีมยืนยัน) เป็นแหล่งระดับน้ำของ RiskEngine และระบบตรวจทันทีเมื่อมีรายงานน่าเชื่อถือใหม่
- **หลังบ้าน** `/admin/reports` (สิทธิ์ `reports.moderate`): แท็บรอตรวจ / แสดงอยู่ / ยังไม่มีคนยืนยัน / หมดอายุ / ซ่อน, ยืนยัน แสดง ซ่อน ปฏิเสธ ทีละรายการหรือหลายรายการ, เปิดเป็นเคสขอความช่วยเหลือพร้อมพิกัด, เจ้าหน้าที่บันทึกระดับน้ำเอง
- **แอปภาคสนาม**: ปุ่ม "รายงานระดับน้ำตรงนี้" ในแท็บทีม (ถือว่ายืนยันแล้ว ใช้ออฟไลน์ได้) และจุดรายงานบนแผนที่
- **ศูนย์สั่งการ/ทีวี**: ชั้นรายงานระดับน้ำบนแผนที่ และตัวเลขรายงานที่แสดงอยู่

## เฟส 8: สถานีวัดน้ำ พยากรณ์ฝน เตือนภัยล่วงหน้า และ CCTV

- **สถานีวัดน้ำ** (`/admin/stations`): เกณฑ์ ตลิ่ง / เฝ้าระวัง / เตือนภัย / วิกฤต, กราฟระดับน้ำพร้อมเส้นเกณฑ์ (Chart.js), แนวโน้ม ซม./ชม., เทียบตลิ่ง
  - รับข้อมูลได้ 3 แบบ: บันทึกเอง, นำเข้า CSV (รองรับปี พ.ศ.), ดึงจาก JSON API อัตโนมัติทุก 10 นาที (`flood:fetch-stations`) ระบุตำแหน่งค่าแบบ `data.0.value`
  - การดึง URL ภายนอกผ่าน `SafeUrl` กันยิงเข้าเครือข่ายภายใน (SSRF) และตรวจซ้ำทุก redirect
  - ไม่มีค่าใหม่เกิน 6 ชม. = ขาดการติดต่อ
  - สถานีที่เกินเกณฑ์เป็นแหล่งระดับน้ำของ RiskEngine ตามรัศมีอิทธิพลของสถานี (เฝ้าระวัง=1, เตือนภัย=2, วิกฤต=3)
- **พยากรณ์ฝน 7 วัน** จาก Open-Meteo (ฟรี ไม่ต้องใช้คีย์) รายอำเภอ ทุกชั่วโมง (`flood:fetch-forecast`) แสดงหลังบ้านและเว็บประชาชน
- **เตือนภัยล่วงหน้า** (`/admin/alerts`)
  - ระบบประกาศเอง: สถานีเกินเกณฑ์, ฝนพยากรณ์เกิน 35 / 90 มม. ใน 3 วัน (ตั้งค่าได้), จุดเสี่ยงความรุนแรงสูงถูกน้ำคุกคาม
  - ใช้ key กันประกาศซ้ำ สถานการณ์รุนแรงขึ้นจะอัปเดตประกาศเดิมและต้องรับทราบใหม่ กลับปกติแล้วปิดเอง
  - ศูนย์ประกาศเองได้ เลือกอำเภอ ตั้งเวลาหมดอายุ เลือกแสดงสาธารณะ
  - ศูนย์สั่งการ/ทีวี มีแถบประกาศ เสียงเตือนเมื่อมีประกาศใหม่ และปุ่มรับทราบ, แอปภาคสนามเห็นประกาศบนแท็บงาน
- **กล้อง CCTV** (`/admin/cctv`): ภาพนิ่งรีเฟรชเอง, HLS (hls.js), ฝังหน้าเว็บแบบ sandbox, หรือลิงก์ บังคับ https, ผูกกับสถานีได้, โหลดภาพเฉพาะกล้องที่อยู่บนจอ
- **เว็บประชาชน**: แถบประกาศเตือนภัย, พยากรณ์ฝน, ระดับน้ำที่สถานี บนหน้าจังหวัด และชั้นสถานี/กล้องบนแผนที่สถานการณ์

## เฟส 9: ศูนย์พักพิง ผู้อพยพ คลังของบริจาค ประกาศ และ LINE OA

- **ศูนย์พักพิง** (`/admin/shelters`): สถานะ เตรียมเปิด / เปิดรับ / เต็ม / ปิด, จำนวนรับได้ เปลี่ยนเป็น "เต็ม" และกลับเป็น "เปิดรับ" เองตามจำนวนคน, สิ่งอำนวยความสะดวก, กำหนดเจ้าหน้าที่ประจำศูนย์ (เห็นเฉพาะศูนย์ตัวเอง)
- **ผู้อพยพ**: ลงทะเบียนทั้งครอบครัวในครั้งเดียว (รหัสครอบครัว), ช่วงอายุ ภาวะที่ต้องดูแล, ออกจากศูนย์/ย้ายศูนย์ทั้งครอบครัว, ลงทะเบียนต่อจากเคสที่ทีมส่งเข้าศูนย์ได้จากหน้าเคส
  - ไม่เก็บเลขบัตรประชาชน เบอร์โทรเข้ารหัส ค้นหาด้วย hash
- **ค้นหาญาติ** `/{จังหวัด}/find`: ใส่เบอร์โทรให้ตรงทั้งเบอร์ แสดงชื่อแบบปิดบังและศูนย์ที่อยู่ เฉพาะคนที่ยินยอม จำกัด 10 ครั้ง / 10 นาที
- **ศูนย์ต้องการอะไร**: แต่ละศูนย์ลงรายการของที่ขาด แสดงบนเว็บประชาชนให้บริจาคตรงจุด
- **คลังของบริจาค** (`/admin/supplies`): คลังกลาง + คลังย่อยที่ศูนย์, รับเข้า (ระบุผู้บริจาค) / จ่ายออก / โอน / ตรวจนับ, กันจ่ายเกินด้วย lock, ยอดคำนวณจากรายการเคลื่อนไหว ตรวจย้อนหลังได้, เตือนของใกล้หมด
- **ประกาศ** (`/admin/announcements`): ข่าวสาร / เฝ้าระวัง / ด่วน, ประชาชนหรือเฉพาะเจ้าหน้าที่, เลือกอำเภอ, ปักหมุด, ร่างไว้ก่อนได้, สร้างจากประกาศเตือนภัยได้ในคลิกเดียว
- **LINE OA** (ตั้งค่า > LINE OA, token/secret เก็บแบบเข้ารหัส)
  - ประกาศถึงประชาชน = broadcast ถึงผู้ติดตามทุกคน, ถึงเจ้าหน้าที่ = multicast ถึงผู้ใช้ที่ผูก LINE, บันทึกผลการส่ง ส่งซ้ำได้
  - Webhook `/line/webhook/{จังหวัด}` ตรวจลายเซ็น: ส่งตำแหน่งมาแล้วได้ศูนย์พักพิงใกล้สุด 3 แห่งพร้อมลิงก์นำทาง และระดับน้ำที่มีคนรายงานรอบตัว, พิมพ์ "ช่วย" "น้ำ" "ศูนย์" ได้ลิงก์ที่ใช่
- **เว็บประชาชน**: ประกาศจากศูนย์, ศูนย์พักพิงที่เปิดรับพร้อมที่ว่าง, ปุ่มเพิ่มเพื่อน LINE, หน้า `/{จังหวัด}/shelters` เรียงตามระยะจากผู้ใช้, ชั้นศูนย์พักพิงบนแผนที่สถานการณ์
- **ศูนย์สั่งการ/ทีวี**: จำนวนคนในศูนย์พักพิงและศูนย์ที่เปิด

## เฟส 10: รายงานผู้บริหาร ส่งออก และขึ้นเซิร์ฟเวอร์จริง

- **รายงานผู้บริหาร** (`/admin/exports`, สิทธิ์ `exports.view`): เลือกช่วงวันและอำเภอ
  - เคสทั้งหมด ช่วยแล้ว คนที่ช่วยออกมา เคสค้าง กลุ่มเปราะบาง ข้อมูลไม่จริง
  - **เวลาตอบสนอง** นับจากแจ้งถึง ทีมตอบรับ / ถึงที่เกิดเหตุ / ช่วยเสร็จ แสดงค่ากลาง ค่าเฉลี่ย และ 90 เปอร์เซ็นไทล์ (ค่ากลางไม่ถูกเคสผิดปกติดึง)
  - กราฟเคสเข้าใหม่และปิดรายวัน, ตารางรายอำเภอ, ผลงานแต่ละทีม (รวมจำนวนปฏิเสธและเวลาเดินทาง), ศูนย์พักพิง, ของบริจาครับ/จ่าย
- **รายงานสถานการณ์ (SitRep)** `/admin/exports/sitrep`: หน้า A4 พร้อมพิมพ์หรือบันทึก PDF จากเบราว์เซอร์ มีช่องลงนาม
- **ส่งออก CSV** (UTF-8 BOM เปิดใน Excel ภาษาไทยได้ทันที): เคส, งานของทีม, ผู้อพยพ, รับ-จ่ายของ, รายงานระดับน้ำ, ค่าสถานี
  - stream ทีละชุด ส่งออกหลายหมื่นแถวได้ไม่กินหน่วยความจำ
  - เบอร์โทรปิดบังเป็นค่าเริ่มต้น เบอร์เต็มต้องมีสิทธิ์ และบันทึกในประวัติการใช้งานทุกครั้ง
  - กันสูตร Excel ที่แฝงมากับข้อความที่ประชาชนกรอก (CSV injection)
- **ข้อมูลเปิด** `/{จังหวัด}/open-data.json`: ตัวเลขสรุป ศูนย์พักพิง สถานีวัดน้ำ ประกาศเตือนภัย ไม่มีข้อมูลส่วนบุคคล เปิด CORS ให้หน่วยงานอื่นดึงไปแสดงได้
- **PDPA**: `flood:prune-data` ทุกวัน ลบเบอร์โทรของเคสที่ปิดและผู้อพยพที่ออกจากศูนย์เกิน `PII_RETENTION_DAYS` (ค่าเริ่มต้น 180 วัน) เหลือแต่สถิติ
- **ความปลอดภัย**: header ความปลอดภัยทุกหน้า, หลังบ้านห้ามแคชและห้ามติด search engine, รองรับ reverse proxy (`TRUSTED_PROXIES`), หน้าแผนที่สาธารณะฝังในเว็บอื่นได้
- **ชุดขึ้นเซิร์ฟเวอร์** ในโฟลเดอร์ `deploy/` และคู่มือ [docs/DEPLOY.md](docs/DEPLOY.md): nginx (รวม Reverb ผ่าน 443), supervisor (queue + Reverb), crontab, สคริปต์สำรองข้อมูล, สคริปต์อัปเดตเวอร์ชัน และเช็กลิสต์ก่อนเปิดใช้จริง

## เฟส 11 (เสริม): โหมดฟื้นฟูหลังน้ำลด

- **เปิดเมื่อพร้อม**: ปุ่ม "ตั้งค่า" ในหน้า `/admin/recovery` เปิดให้ประชาชนยื่นคำร้องที่ `/{จังหวัด}/recovery` (ปิดไว้เป็นค่าเริ่มต้น) เจ้าหน้าที่บันทึกคำร้องแทนได้ตลอด
- **คำร้อง**: ความเสียหายของบ้าน 4 ระดับ ทรัพย์สิน 7 ประเภท พื้นที่เกษตร สัตว์ รูปสูงสุด 5 รูป ปักหมุดบ้าน เบอร์เดียวกันมีคำร้องค้างได้ทีละ 1 คำร้อง
- **หลักฐานอัตโนมัติ (ลดคำร้องปลอม จัดลำดับงานสำรวจ)**: ระบบตรวจจากข้อมูลช่วงน้ำท่วมให้เอง
  - เบอร์นี้เคยแจ้งขอความช่วยเหลือ (+40) / เคยอยู่ศูนย์พักพิง (+40)
  - มีรายงานน้ำหรือเคสในรัศมี 500 ม. (+25) / ตำบลที่ศูนย์ประกาศระดับน้ำ (+20) / อยู่ในทะเบียนครัวเรือนเปราะบาง (+10)
  - แจ้งเตือนเมื่อมีคำร้องอื่นในรัศมีประมาณ 50 ม. (อาจซ้ำ)
- **ขั้นตอน**: รอสำรวจ → นัดสำรวจ (มอบหมายผู้สำรวจ) → บันทึกผลสำรวจหน้างานจากมือถือ (ถ่ายรูปได้) → อนุมัติ → จ่าย / ไม่ผ่านเกณฑ์ ข้ามขั้นไม่ได้ จ่ายเกินยอดอนุมัติไม่ได้
- **ยอดแนะนำ**: ตั้งอัตราตามระเบียบที่หน่วยงานใช้จริง (บ้านตามระดับ ทรัพย์สินแต่ละประเภท พืชผลต่อไร่ เพดานต่อครัวเรือน) ระบบคำนวณยอดแนะนำหลังสำรวจ ผู้อนุมัติกำหนดยอดจริงเอง
- **สิทธิ์ใหม่**: `recovery.manage` (อนุมัติ จ่าย) และ `recovery.survey` (สำรวจ ให้หัวหน้าทีมกู้ภัยและเจ้าหน้าที่สั่งการไว้แล้ว) ระบบที่ติดตั้งไว้ก่อนให้รัน `php artisan db:seed --class=RolePermissionSeeder`
- **ประชาชนติดตามสถานะ** ด้วยลิงก์เซ็นชื่อ หรือเลขคำร้อง + เบอร์โทร เห็นขั้นตอนและยอดที่อนุมัติ
- ส่งออก CSV คำร้องเยียวยาได้ในหน้ารายงานและส่งออก

## ปรับปรุงก่อนใช้งานจริง

- **งานหนักย้ายไปทำเบื้องหลัง (queue)**: ส่ง LINE (`SendAnnouncementLine`) และตรวจจุดเสี่ยงเมื่อมีรายงานน้ำที่น่าเชื่อถือ (`EvaluateProvinceRisks` รวบหลายรายงานเป็นรอบเดียวต่อจังหวัด) ต้องมี queue worker ทำงาน (ดู `deploy/supervisor.conf`)
- **แคชข้อมูลศูนย์สั่งการ**: ทุกจอของจังหวัดใช้ snapshot ชุดเดียวกัน หมดอายุทันทีเมื่อข้อมูลเปลี่ยน (นับเวอร์ชันผ่าน `Live::bump`) หรือ 15 วินาที จอหลายสิบเครื่องไม่ทำให้ฐานข้อมูลหนัก
- **ยืนยันตัวตน 2 ชั้น**: TOTP เขียนเองตาม RFC 6238 (ผ่านค่าทดสอบของมาตรฐาน) ไม่ต้องลง package, QR สร้างในเบราว์เซอร์ รหัสลับไม่ส่งออกไปที่อื่น, กันใช้รหัสเดิมซ้ำ, รหัสสำรอง 8 รหัส, บังคับตามบทบาท, ใช้กับทั้งเข้าด้วยเบอร์โทรและ LINE
- **หมดเวลาเมื่อไม่ใช้งาน** (`IDLE_TIMEOUT_MIN`): การดึงข้อมูลเบื้องหลังไม่นับ จอทีวีเป็นโหมด kiosk แอปภาคสนามไม่หมดเวลา
- **ประกาศความเป็นส่วนตัว** `/{จังหวัด}/privacy` พร้อมข้อความแจ้งใต้ทุกฟอร์มที่เก็บข้อมูลส่วนบุคคล กรอกหน่วยงานผู้ควบคุมข้อมูลและ DPO ในหน้าตั้งค่า (ควรให้ฝ่ายกฎหมายตรวจทาน)
- **ข้อมูลตัวอย่าง** `php artisan db:seed --class=DemoSeeder` (ไม่ยอมรันบน production): บัญชี 7 บทบาท ทีม เคสทุกสถานะ จุดเสี่ยง สถานีพร้อมค่า 72 ชม. รายงานน้ำ ศูนย์พักพิงและผู้อพยพ คลัง ประกาศ คำร้องเยียวยา เข้าด้วย 0990000001 ถึง 0990000007 รหัส demo1234
- **ทดสอบโหลด** `deploy/loadtest/k6-public.js` (ดู docs/DEPLOY.md หัวข้อ 9)

## ติดตั้ง

> ขึ้นเซิร์ฟเวอร์จริงดู [docs/DEPLOY.md](docs/DEPLOY.md)

```bash
composer install
cp .env.example .env
php artisan key:generate
# แก้ DB_* และตั้ง SUPERADMIN_PHONE / SUPERADMIN_PASSWORD ของตัวเองใน .env ก่อน seed
# สร้างฐานข้อมูล floodthai (utf8mb4_unicode_ci) แยกจากระบบอื่น
php artisan migrate --seed
php artisan storage:link
php artisan serve
```

เข้าระบบที่ `/login` ด้วย `SUPERADMIN_PHONE` / `SUPERADMIN_PASSWORD` ที่กำหนดเองใน `.env` แล้วเปลี่ยนรหัสผ่านทันทีหลังติดตั้ง

โฮสต์ทั่วไปตั้ง Cron ทุกนาทีเรียก `php /path/artisan flood:cron` (PHP CLI 8.3 ขึ้นไป)
VPS ที่มี queue worker แยกดู [คู่มือขึ้นเซิร์ฟเวอร์](docs/DEPLOY.md) อย่าตั้งงานสองรูปแบบซ้ำกัน

## นำเข้าขอบเขตอำเภอ/ตำบล

แนะนำชุดข้อมูล Thailand Subnational Administrative Boundaries (COD-AB) จาก HDX
ไฟล์ ADM2 = อำเภอ, ADM3 = ตำบล (ระบบอ่านคอลัมน์ ADM2_TH, ADM2_PCODE, ADM3_TH, ADM3_PCODE ให้เอง)

- ไฟล์จังหวัดเดียว: เมนู อำเภอและตำบล > นำเข้า GeoJSON (นำเข้าอำเภอก่อนตำบล)
- ไฟล์ทั้งประเทศ:

```bash
php artisan flood:import-areas storage/app/tha_adm2.geojson --level=district --province=all
php artisan flood:import-areas storage/app/tha_adm3.geojson --level=subdistrict --province=all
```

ไฟล์ทั้งประเทศมีขนาดใหญ่ ควร simplify geometry ก่อน (เช่นด้วย mapshaper `-simplify 10%`) เพื่อให้แผนที่โหลดเร็วบนมือถือ
